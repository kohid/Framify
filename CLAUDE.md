# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Framify is a single WordPress plugin (no build step, no package manager, no test suite, not a git repo). It stores CSS/JS/PHP/HTML snippets in custom tables and injects them into the site, and ships two full-page apps that run **outside** wp-admin: a live code editor and an SEO analyser.

Development is edit-file → reload page. There is nothing to compile, lint, or run.

## Working agreement

Always work in collaboration with `/feature-dev:feature-dev` and `/frontend-design:frontend-design`, whether or not the request names them: feature-dev for the workflow (explore, clarify, design, implement, review), frontend-design for every visual or UI decision.

## Verifying behaviour

The host site (`business-directory`, Local by Flywheel) has **no wp-cli**. To check DB-backed behaviour for real, query MySQL over TCP — see the `local-site-mysql-access` memory for how to derive the port (it is not discoverable from `netstat`). Tables: `wp_framify_codes`, `wp_framify_revisions`.

`FRAMIFY_VERSION` in [framify.php](framify.php) is the cache-buster appended to every enqueued asset URL. **Bump it whenever you change a file under `assets/`** or browsers will serve the stale copy.

## Architecture

### Snippet storage and schema

Two tables, both defined once in `Framify::get_schema_sql()` — that method is the single source of truth for a fresh install *and* every migration, so they cannot drift. Migration runs on `plugins_loaded` (`maybe_upgrade_db`), gated by the `framify_db_version` option, because `register_activation_hook` does not fire when plugin files are replaced in place. `run_schema_migration()` deliberately does **not** trust dbDelta's return — it confirms the newest column exists via `schema_is_current()` before recording the version, so a failed ALTER retries instead of leaving a half-migrated install.

If you add a column: add it to `get_schema_sql()`, bump `FRAMIFY_DB_VERSION`, and point `schema_is_current()` at the new column.

### Snippet delivery

`output_code($position, $location)` runs on `wp_head`/`wp_body_open`/`wp_footer`/`admin_head`/`admin_footer`/`login_head`. It selects active rows matching `where_on_page` + `where_in_site`, orders by `priority ASC, id ASC`, then filters each through `should_display_code()` (the JSON `url_rules` matcher — any rule matching wins, an empty ruleset means "everywhere").

Output shapes matter downstream:

- CSS/JS get `framify_cache_exclusion_attrs()` spliced into the tag, including a stable `data-framify="css-<id>"` marker. The live editor finds saved snippets by that attribute.
- HTML is **delimited by comments** (`<!--framify-html-ID-->` … `<!--/framify-html-ID-->`), never wrapped in an element, so a snippet's own DOM structure and selectors survive. The editor walks siblings between those comment nodes to hide the saved copy while you edit.

PHP snippets are separate: `execute_php_snippets()` runs on `init` and `eval('?>' . $content)` each one, same priority ordering.

### always_run and caching

PHP never executes on a full-page cache hit, so a snippet doing per-request work (redirect, cookie, per-visitor output) would silently do nothing. Flagging it `always_run` makes `maybe_force_nocache()` (hooked on `wp`, not earlier — the `first-page` URL rule needs `is_front_page()`) call `framify_force_nocache()`. The "are there any flagged snippets at all" answer is cached in the `framify_has_always_run` option and invalidated by `framify_code_changed`, so the common path costs one autoloaded read.

[framify-cache.php](framify-cache.php) is the compatibility layer. `framify_cache_purgers()` is a declarative registry — adding a cache plugin is one array entry, and every purger is wrapped so a renamed vendor function no-ops rather than fatals. Purges are collapsed to one per request via `shutdown`. There is deliberately no generic `wp_cache_flush()` purger; the comment at line ~154 explains why.

Extension points: `framify_code_changed`, `framify_cache_purgers`, `framify_cache_exclusion_attrs`, `framify_before_cache_purge` / `framify_after_cache_purge`, `framify_nocache_forced`.

### The two front-end apps

Both bypass wp-admin entirely: a query param on the front page is intercepted on `template_redirect`, verified against a nonce **and** `manage_options`, then a full `<!DOCTYPE html>` document is echoed and `exit`. Entry points are in the admin bar (`add_framify_admin_bar_button`), which passes the current URL through as `preview_url`.

- `?framify_preview=1&token=…` → [templates/live-preview-frontend.php](templates/live-preview-frontend.php) + [assets/live-preview-script.js](assets/live-preview-script.js)
- `?framify_seo=1&token=…` → `Framify_SEO::render_seo_page()`

Both call `framify_print_frame_guard()` before the iframe is parsed. That stub exists because Elementor Pro's Notes module ends with an unguarded `window.top.$e.…`, which throws inside our iframe; the docblock explains why the stub cannot fool a script into thinking it is in the editor.

### Shortcodes

`[framify_code]` and `[framify_seo]` place either tool on an ordinary page. Both branch on capability, and that branch is load-bearing: the code editor writes PHP snippets that `execute_php_snippets()` runs through `eval()`, so an embed a visitor could use would be remote code execution. An administrator gets the real tool in an **iframe** pointing at the existing nonce-gated endpoint — never an inlined copy, both because the gate is worth keeping and because those endpoints emit whole `<!DOCTYPE html>` documents and `exit`. Everyone else gets inert demo markup built from the same `--fr-*` tokens, with no iframe, token or endpoint URL anywhere in the output. `demo="yes"` forces the visitor view so that can be checked without logging out.

The live branch calls `framify_force_nocache()`: the token is per-user and expires, so a page cache would otherwise serve one stale nonce to everybody.

Style loading is deliberately belt-and-braces. `has_shortcode( $post->post_content, … )` misses Elementor and Divi layouts, which keep content outside `post_content` — so the shortcode callbacks enqueue again as a fallback.

### Live editor

Four CodeMirror instances (CSS / jQuery / PHP / HTML) over a same-origin iframe. Preview is applied by reaching into `iframe.contentDocument` directly — there is no postMessage channel.

The non-obvious part is that the *saved* copy of a snippet has to be suppressed while you edit it, or edits look additive instead of replacing:

- `muteSavedStyle()` sets `.disabled` on `style[data-framify="css-<id>"]` — an empty rule cannot un-declare what the saved copy already set.
- `hideSavedHtml()` / `savedHtmlElements()` walk the comment markers described above and restore the previous `display` before hiding anything new.

CSS and HTML preview live. **jQuery and PHP have no live path** — they go through save + `reloadPreviewIframe()` (which cache-busts with `_fvcache`). After any iframe load the script re-applies CSS and HTML.

### SEO analyser

`ajax_seo_analyse` parses markup with DOMDocument/DOMXPath server-side; all scoring and rendering happens in JS. It reads markup two ways: **Analyse** uses `wp_remote_get` (what a crawler's first pass sees), and **On screen** posts `documentElement.outerHTML` from the preview frame in an optional `html` param, which is the only way to see content that JavaScript created — infinite scroll, "load more". The `wp_remote_get` happens either way, because HTTP status, HTTPS and the response headers are properties of the response rather than the DOM, and dropping them would make the two modes score differently for reasons unrelated to the page. The response carries `mode` so the panel can say which reading produced it.

**That self-request is a re-entrancy hazard.** The handler fetches this same site over HTTP from inside a request WordPress is already serving, so it holds one PHP worker while waiting for a second. Local by Flywheel serves two per site — see the `local-site-php-worker-limit` memory. Two overlapping runs therefore deadlock until cURL gives up at 15s (`0 bytes received`), which is why `run()` is guarded by an in-flight flag and why the preview iframe is only refreshed *after* the response, never alongside it. Do not add a third concurrent PHP request to this path. Two write paths: `ajax_fix_alt` writes `_wp_attachment_image_alt` on a media-library attachment, and `ajax_save_schema` inserts a JSON-LD block as an ordinary `html` snippet in `wp_framify_codes` scoped to that page's path — so schema you "save" from the analyser is thereafter a normal Framify snippet. That handler re-encodes the JSON from the decoded value with `JSON_HEX_TAG` rather than trusting the submitted string; do not simplify that away.

### Theming

`assets/framify-themes.css` is the single source of truth: `--fr-*` tokens for five themes plus the `.fr-theme*` picker. Theme blocks are dual-scoped — `[data-framify-theme]` paints real UI, `[data-preview-theme]` paints the miniature inside a picker card. Load it *before* any stylesheet that consumes the tokens.

Applying a theme = swapping `data-framify-theme` on `<html>`, rendered server-side so there is no flash. Persisted per user in the `framify_ui_theme` user meta. Each theme maps to a matching CodeMirror syntax theme via `framify_ui_themes()`; the live-preview template preloads every mapped CM theme so switching is instant.

Both the code editor and the SEO analyser render the same Appearance modal (`#framify-settings-modal`) over the same `.fr-theme` picker cards, and write to the same user meta — so a theme picked in one applies to the other. The picker markup is duplicated in [templates/live-preview-frontend.php](templates/live-preview-frontend.php) and [framify-seo.php](framify-seo.php), but its CSS lives once in `framify-themes.css`; keep it that way, or the two pickers will drift.

Severity colours are themed too: `--fr-pass` / `--fr-warn` / `--fr-fail` (plus `-soft` fills) are defined per theme rather than fixed. That is not cosmetic — a single global triple put warn on top of Ember's amber accent, and left green and amber near 1.9:1 on the two white themes. If you add a theme, define all six or the analyser's pass/warn/fail states go colourless.

`assets/framify-gutenberg.css` is the one stylesheet **not** migrated — it still carries the hardcoded `#667eea → #764ba2` purple.

### Elementor module

[framify-elementor.php](framify-elementor.php) registers a `framify` panel tab (`Controls_Manager::add_tab`) on the Image widget, Containers and the Spacer widget, currently holding one feature, **Organic Shape**: clip to an organic blob that springs into a second blob on hover / scroll-in / loop, plus an optional coloured, grainy "deco" blob behind. It is the reference site's Codrops "organic shape" effect, rebuilt without anime.js.

- **Tab position** follows the order sections are registered, so controls hook `after_section_end` on each element's *last* section (`section_style_caption`, `_section_responsive`, the Spacer's `section_spacer`) to land the tab at the end. Hooking an earlier section wedges it between Content and Style.
- **Shapes** are 8-radius rings run through one Catmull-Rom builder (`build_path`), so every rest/hover pair shares an identical path structure. That is the whole morph engine: [assets/framify-elementor.js](assets/framify-elementor.js) blends the numbers in the two strings. A hand-drawn path with a different command sequence will not morph; add presets as Blob radii rings, Wavy wave parameters, or Flow hand-placed anchors, never as hand-written paths.
- **All work happens in the JS handler**, in the editor preview and on the live site alike. Controls are `frontend_available` + `render_type: none`, and `onElementChange` rebuilds in place. PHP render hooks would not show in the editor: the Image widget previews through its own JS template.
- **How settings reach the JS (applies to Floating Shapes too).** Published pages get `Controls_Stack::get_frontend_settings()` (elementor/includes/base/controls-stack.php): it starts from `get_settings_for_display()`, which **includes control defaults**, then **drops every `null` or `''` value**. The editor sends the model's values, with `''` for an off switch or a cleared colour. So a missing key means *empty*, never *default*: read a SWITCHER as `'yes' === value` (never "missing = default on"), and treat a missing COLOR as cleared. Fallbacks are only harmless for selects/sliders whose default is non-empty (always present anyway). Every COLOR control has Elementor's Global Colour picker disabled on purpose (`'global' => array( 'active' => false )`): a linked value lives only in `__globals__`, which reaches neither `data-settings` nor the editor's active settings, so it would silently read as empty/default.
- The real `<img>` is **clipped, not replaced** (`clip-path: url(#...)` to an `objectBoundingBox` clipPath), keeping srcset/alt/lazy-load/links. Image zoom scales the `<img>` and shrinks the clip path by the same factor (`clipTransform()`), so the photo zooms inside a blob that stays put.
- Its assets are versioned by `filemtime()`, not `FRAMIFY_VERSION` (docblock explains why), so no bump is needed when editing them.
- **Three built-in shape families (plus Custom).** Blobs (radial ring, `build_path`) and Wavy (`wavy_anchored` / `wavy_free`: superellipse pushed in by two whole-number-frequency waves), and Flow (hand-placed anchors, below). Wavy is drawn with a straight *right* edge; the JS turns it to left/top/bottom with an SVG transform (`EDGE_TRANSFORM`) and uses the `free` variant for "none". Keep `inset >= amp1 + amp2` or the outline leaves the box.
- **Placement is CSS, not settings.** Responsive controls write `--framify-*` / `--framify-deco-*` custom properties on the wrapper; `readBox()` reads computed style, so breakpoints work with no JS plumbing. Anything that changes the flat edge (e.g. Auto edge + a new horizontal position) rebuilds the element, because the path itself changes.
- **Trigger "auto"** = hover for Blobs, static for Wavy, Flow and Custom (Elementor can't vary one control's default by another).
- **Float** (`register_float_controls`, hooked on both `common` and `common-optimized`) is pure CSS animating `translate`/`rotate`, so it composes with Elementor's Transform/Motion Effects. It conflicts with an Entrance Animation on the same widget (both set `animation`). **Containers:** the same function is also hooked on `elementor/element/container/_section_responsive/after_section_end` at 40 (after Organic Shape / Grain 10, Floating Shapes 20, Floating Text 30), same ids, prefix class and `{{WRAPPER}}` custom properties; only the container's `framify_float` switch gets a description ("Float works on containers placed inside another container. It replaces an Entrance Animation on the same container."). **Nested only, gated in CSS:** `.e-con.framify-float-yes:not(.e-child) { animation: none; }` in `framify-elementor.css` outranks the widget rule, so a top-level container (`.e-parent`) with Float saved stays still; Elementor derives `e-child` / `e-parent` from the model's `isInner`, in PHP (`includes/elements/container.php`) and in the editor view alike. **Panel hiding (editor only):** `assets/framify-elementor-editor.js` (enqueued on `elementor/editor/after_enqueue_scripts`, the editor window, not the preview) hooks `elementor.hooks.addAction( 'panel/open_editor/container', ... )` and toggles `.framify-float-off` on the whole panel (`elementor.getPanelView().$el`) when the model is not inner; `framify-elementor-editor.css` hides `[class*="elementor-control-framify_float"]` under it (section heading + controls). Not on the editor page view: a tab switch replaces that view in Elementor 4.2.4, losing the class. `panel/open_editor/widget` / `section` / `column` clear it, so widgets keep their Float section. Legacy Sections do not get Float.
- **Geometry tests:** `php dev/tests/elementor-shapes-test.php` (CLI only). Run `--baseline` before touching Blob geometry, `--preview` to eyeball shapes.
- **Flow family** (`flow_presets()`): hand-placed anchors from (100,0) round to (100,100), drawn by `smooth_path( $points, false )`; hover = the same anchors nudged <= 6 units. No free variant, so Flat edge "None" means right. Tune anchors only; the CLI test guards corner pins, 8-14 anchors and drift.
- **Auto flat edge** only picks a side the placement box actually reaches, within a small tolerance (`box.x <= 0.001` / `box.x + box.w >= 0.999`); otherwise Wavy drops the edge and Flow falls back to the side it touches, else right.
- **Custom shape** (`framify_org_shape = custom`, `framify_org_custom_svg`): parsed in the browser (`parseCustom`). Security rule: only path data matching the SVG path character set is kept, and only via `setAttribute('d')`, with a leading `m` prefixed by `M0 0` so joined paths stay absolute; pasted markup is never inserted. Fitted into the 0-100 box by `customTransform()` (innermost part of `fx.inner`; see Custom flat edge and Flip / Rotate below for what wraps it). Static unless a motion trigger is set (see Motion below); when static or Gentle, its raw `d` is written as pasted, never through the morph's number blender (keeps packed arc flags and precision); not offered for the Image widget's deco. Motion (only with a Hover / In view / Loop trigger; Auto stays static): `framify_org_custom_motion` Liquid (`traceCustom`: 400 samples split into parts at movetos, 96 points shared by length, normal-wave hover pose, same Catmull-Rom as PHP `smooth_path`; inner transform = flip/rotate + flat-edge turn only) or Gentle (raw `d` kept, `fx.inner` animated by `gentleTransform` around the box centre; the rotation is conjugated with the shape box's rendered pixel aspect, via a 4th `aspect` argument, so a non-square element rotates instead of shearing); amounts in `CUSTOM_AMOUNT`; Liquid falls back to Gentle when tracing fails. The trace memo is keyed on path + box + amount + pinned side; the ripple is scaled per part by `min(1, perimeter/60)` so small parts don't invert; normals use a tangent smoothed over 3 neighbours each side; sharp-cornered shapes can show a small horn at Strong, so use Gentle for them. Liquid drops parts shorter than 1% of the traced length (e.g. the dot of an i), and with a tight viewBox plus 100% Placement, Gentle's swell and Liquid's outward ripple can be cropped at the element edge in Clip mode; give the paste some viewBox padding or reduce Width/Height (Containers now bleed their background past the box instead, see "Container clip bleed"; the Image widget insets, see "Image widget motion inset").
- **Custom flat edge** (the `framify_org_edge` control now also shows for `custom`). `measureCustom()` runs once per paste (memoised with `parseCustom`, whose result gains `bbox` and `straight`): hidden-svg `getBBox()` + 240 `getPointAtLength()` samples; for each side of the path's OWN bbox, the longest run of consecutive samples within 0.6% (of the bbox dimension across that side) of the side line; run extent along the side / side length = coverage; best side wins if coverage >= 0.5, else `straight: null`. `resolveEdge( family, setting, box, custom )`: for Custom only an explicit left/right/top/bottom (with a detected straight side) turns and refits it; Auto and None = as pasted (viewBox fit). Auto is deliberately NOT position-driven for Custom: it is the always-present default, so existing custom elements stay unchanged (a position-driven Auto silently refitted and turned them). No straight side = always none, with one editor warning per paste only for an explicit left/right/top/bottom. `customFit( custom, edge )`: with a flat edge the path is fitted by its bbox (straight side exactly on the box edge) and turned `EDGE_TRANSFORM[target] EDGE_INVERSE[detected]`; with none it keeps the old viewBox fit, no turn (existing elements unchanged). Liquid traces with that same box and keeps only the turn as its inner; its ripple is pinned to the straight side (`ripplePoints` pin, fading over `PIN_TAPER` = 10 box units) so the side stays flush on hover like Wavy/Flow. Gentle wraps the full custom inner (flip/rotate + turn + fit), still aspect-conjugated.
- **Flip / Rotate** (`framify_org_flip_h`, `framify_org_flip_v`: switches, every main shape; `framify_org_custom_rotate`: 0/90/180/270, Custom only, gated on the family in `readOrient()` because a hidden value survives a shape switch). `orientTransform()` = flips then `rotate(R 50 50)`, the OUTERMOST part of `fx.inner`. Inner order as written (SVG applies right to left): `orient turn fit` for Custom, `orient EDGE_TRANSFORM[edge]` for built-ins; the container deco path and Gentle use the same `fx.inner`. The Image widget's own deco blob is not flipped. Zoom origin uses `fx.zoomSide = orientSide( edge, orient )`: each 90 deg moves a side clockwise (right > bottom > left > top), then flip H swaps left/right and flip V top/bottom, so zoom never opens a gap on the straight side.
- **Image widget motion inset** (Custom shape + Liquid / Gentle on the Image widget's main clip only; built-ins, containers, the Spacer and the deco are untouched). An img has no pixels past its own box, so the outward part of a ripple / swell was cut in straight lines at the photo edges when the zoom did not grow the photo enough. `place()` pulls each side of the placement box in by `motionInset( box, fx.zoomSide, fx.motion, aspect, fx.zoom, fx.over )` (via `insetBox()`, before `zoomOrigin` / `clipTransform`): reach at the value's peaks (`motionReach`: Liquid = ripple x |v| box units, i.e. 2 / 3.5 / 5% of the box for subtle / normal / strong; Gentle = worst case of a box-filling shape swollen by `scale` and rotated in pixel space, ~2.3 / 4.6 / 8% on a square box), minus the room the side already has inside the img, minus the zoom's cover. The clip is counter-scaled by 1/zoom, so the shape stays put on screen while the photo grows about the origin past each img edge by (zoom - 1) x the origin's distance to that edge (fractions of the img box). Peaks: 1 + over with its zoom, and -over (zoom stays 1, Liquid's inward pushes flip outward); `fx.over` = `springOvershoot()` (0 for Loop, elastic peak - 1 otherwise: 0.10 / 0.24 / 0.37). The flat side (`fx.zoomSide`) is never inset. Nothing to inset = the same box object, so clip strings stay identical (e.g. Liquid Strong Loop at the default 10% zoom with a centred origin insets 0). Gentle's aspect is measured on the inset box.
- **Clip-mode grain** (`framify_org_clip_grain`, default off): a specks-only layer (`buildGrainLayer`) as the clipped container's first child at z-index -1; shares `buildGrainFilter()` with the deco blob but draws in real pixels (frequency 0.09) so grain stays round on wide containers.
- **`DEFAULT_SHAPE` must stay a Blob**: the Flat edge condition checks the saved shape, while JS falls back to the default shape.
- **`dev/` is development-only** (CLI tests, guarded by `PHP_SAPI`); it can be left out when copying the plugin to a live site.
- **Grain section** (`register_grain_controls`, its own panel section): containers: `framify_org_deco_grain` / `framify_org_clip_grain` (ids unchanged, moved here); Image widget: `framify_org_grain_target` instead (see below), `framify_org_grain_amount` (0-100, colour-matrix cut = 1.11 - 0.0066 * amount; 50 = the original 0.78) and `framify_org_grain_pattern` (0 = per-element seed from `elementSeed()`, a hash of the element's `data-id`, stable across reloads; else a fixed seed). `grainOptions()` feeds `buildGrainFilter( filterId, specksOnly, frequency, grain )`.
- **Image widget grain target** (`framify_org_grain_target`: deco | image | both | none, default deco) replaces the two switches there; containers keep `framify_org_deco_grain` / `framify_org_clip_grain`. `grainTarget()` resolves it, one `grainOptions()` result feeds both layers (same seed), and `decoLook( s, grain )` takes the resolved options or null (containers pass `grainOn( s ) ? grainOptions() : null`). Image grain = a specks-only `buildGrainLayer( id + '-img', grain, '0.15' )` appended after the img (`.framify-organic__image-grain`, z-index 2, pointer-events none), sized to the img's offset box in `place()`, clipped with the img's own `url(#id)` (objectBoundingBox resolves against the same box) and given the img's transform + transform-origin in `render()`, so it stays locked to the photo while zooming. 0.15 px frequency (not the container layer's 0.09) matches the deco blob's speck size; 0.09 looked like blotchy frost on a photo.
- **Deco Blob section**: every element has its own `framify_deco_section` (Organic Shape, Deco Blob, Grain), with no "Deco Blob" heading, from one `register_deco_controls( $element, 'image' | 'block', $on )`. `'image'` = the Image widget's extra blob; `'block'` = the Spacer AND all Containers (top-level and nested; legacy Sections have no Organic Shape): the extra blob (`framify_org_deco` switch, condition mode = clip) and its shape / placement / motion (mode = clip + deco on), plus the look controls (style, colours, outline width) with `conditions` = `block_deco_visible()` (mode deco OR (clip AND deco on)), so in Behind content mode they style the shape itself (moved there from Organic Shape; same ids, same JS path, the old `framify_org_deco_heading` is gone). Container panel order: Organic Shape, Deco Blob, Grain, Floating Shapes, Floating Text, Float, Shape Divider (Float shows only on nested containers, Shape Divider only on top-level ones). Container Grain = the Spacer's switches (`framify_org_deco_grain` with the same OR, `framify_org_clip_grain` keeps its "container fill" wording). The CLI test checks the Spacer and Image panels unchanged and the Container Deco Blob args equal to the Spacer's.
- **Container Clip mode + Deco Blob** (`framify_org_deco` yes): `setup()` routes it (Spacer or Container: `'clip' === mode && 'yes' === framify_org_deco`) to `setupFill()`, the Spacer model below: background copied into a clipped, oversized fill, the blob (`ownDeco()`, placed in % of the container) behind it, the container not clipped (content, Floating Shapes / Text, border and shadow are no longer cut to the shape; `spill()` lifts an overflow clip on it), clip grain inside the fill, deco grain on the blob, deco channel / rotate as on the Image widget, no `keepHandle()` (nothing clips the handle). Containers rebuild the fill on their own `CONTAINER_FILL_KEYS` (`background_`, `border_`; `fillKeys()` picks, the Spacer keeps `FILL_KEYS`). Deco off = the host clip as before, or the bleed below. Behind content mode is unchanged (the shape is the blob).
- **Clip background only** (`framify_org_mode = bg`, Containers/Spacer): always routed to `setupFill()` (even with the deco off), so only the copied background is clipped to the shape and the content, border and shadow are not; no deco blob is built in this mode (`ownDeco` skipped), and the deco/clip-grain controls stay Clip-mode-only.
- **Container clip bleed** (A0; `fx.bleed`): gate = a Container (not the Spacer) in Clip mode, Custom shape, moving custom motion (`fx.motion` set: Liquid / Gentle with a Hover / In view / Loop trigger, not reduced motion), deco off. Every other clip keeps its old path byte for byte (same clip strings, no fill; checked in the browser against the snapshot). Why: the swell / ripple reaches past the box but the background ended there, so the host clip cut the shape flat. `bleedLayers()`: the clip stays on the host (content stays clipped; a clip-path region is not bounded by the border box), the background moves into an UNclipped `framify-organic__fill` via `takeBackground()` (z-index -1: under Elementor's `::before` overlay, Floating Shapes / Text at 0 and content), clip grain goes inside the fill, `spill()` lifts an overflow clip. The host clip is objectBoundingBox of the host itself, so `place()` does not `fillBox()` it (`fx.fill && ! fx.bleed`). `keepHandle()` still runs (host clip), checked in the editor. **Overlay / video / slideshow:** the host gets `.framify-organic-bleed` and `BLEED_VARS` (`--framify-bleed-t/r/b/l` = the fill margins, `--framify-bleed-tl/tr/br/bl` = the fill's grown radii; rewritten by `refill()`), and framify-elementor.css extends `.e-con::before`, `> .elementor-background-slideshow` and `:is(.e-con, .e-con > .e-con-inner) > .elementor-background-video-container` by them (Elementor's own -border / 100% + borders offsets plus the margins). Elementor uses no `::after` for backgrounds. Not bled: Pro background Motion Effects (`.elementor-motion-effects-container`), the Advanced hover background (suppressed, as on the Spacer), a container border (stays at the box edge).
- **Container fill margin per side** (`fillSides( el, m )`, both container fill paths; the Spacer keeps its single number via `fillMarginFor()`): clip-path does not trim scrollable overflow, so a fill reaching past the page's left / right edge added a horizontal scrollbar on a full-width container; those two sides stop at the document edge (whole px), top / bottom keep m. `takeBackground()`, `fillBox()`, `growRadius()` (each corner grows by its two sides' margins) and `shiftPositions()` (lo - p(lo + hi), the old m(1 - 2p) kept verbatim when both sides are equal) accept the per-side form; `refill()` compares margins with `marginKey()`. **Lazy-loaded backgrounds:** Elementor hides a not-yet-`e-lazyloaded` top-level container's background image (and its descendants') with !important, so a container fill copied too early would keep "none"; `watchLazy()` (containers only) observes that ancestor's class and re-copies once it is loaded.
- **Deco style** (`framify_org_deco_style` solid | outline): `decoLook()` + `buildDeco( id, d, look )`. Outline = stroke with `vector-effect: non-scaling-stroke` (the deco svg is stretched with `preserveAspectRatio="none"`), no grain.
- **Two animation channels** (`fx.channels.main` / `.deco`): every render part has a `channel`; the Image widget's deco uses `deco` when `framify_org_deco_trigger` isn't `same`, with its own duration/spring and `framify_org_deco_rotate` applied as a CSS rotate on the deco svg (pixel space, no shear). Container deco mode always follows `main` (the deco is the shape).
- **Image grain vs Elementor's Hover Animation:** the image grain layer copies only Framify's inline zoom transform, not a CSS `:hover` transform from the Image widget's own Hover Animation (e.g. Grow), so with both on the specks drift off the photo while it hovers. Use Framify's Image zoom instead of a Hover Animation when image grain is on.
- **Spacer = a standalone decor block** (`elementor/element/spacer/section_spacer/after_section_end`, `section_spacer` being the Spacer's only section, elementor/includes/widgets/spacer.php). PHP hooks `register_spacer_controls` there: the container control set (Mode clip / behind content, Deco Blob section, grain switches, same ids; Containers now share the Spacer's Deco Blob layout, see "Deco Blob section"; the CLI test section 7 compares the sets). **Tab position:** a widget's stack is its own controls then the common ones (`Widget_Base::get_stack()` array_merges controls and tabs), so the tab lands after Content and before Advanced, like the Image widget; the Spacer has no Style tab. Its Framify tab: Organic Shape, Deco Blob, Grain, Floating Shapes, Floating Text, then Float (common). **JS:** `attachHandler( 'spacer', OrganicShape )` (widget, default skin); `setup()` works on `paintHost( el )` for `'spacer' === getWidgetType()`, on two paths: Clip mode with "Deco blob behind" on goes to `setupFill()` (see "Spacer deco" below); everything else (Behind content, Clip without a deco) goes to `setupContainer()` exactly like a container, host clip included. **Host = the element that paints the Spacer's Advanced > Background:** the common controls' `_background` selector is `{{WRAPPER}} > .elementor-widget-container`, and with Optimized Markup the Spacer drops that wrapper (`has_widget_inner_wrapper()` false) and "common-optimized" paints `{{WRAPPER}}` itself, so `paintHost()` returns the direct `.elementor-widget-container` child, else the widget element. Clipping that element clips exactly the background (colour or image). With the inner wrapper present the outer widget element (editor handles, Float) is untouched; with Optimized Markup the host IS the widget element, so the clip lands on it (in the editor that also clips the element's editing overlay, as with containers; see "Editor handle"). Its box is the Spacer's height (in a Container the widget-container is 100% of the widget; in a column it wraps `.elementor-spacer-inner`), and the Placement custom properties written on `{{WRAPPER}}` reach it by inheritance. `elementSeed()` reads `data-id` from `closest( '[data-id]' )` because the inner host has none. That host is static, so a class rule (`.elementor-widget-spacer > .elementor-widget-container.framify-organic-container` / `.framify-fs-host`: `position: relative`) keeps it positioned whichever module set the inline position first. **Float** already applies: it is a common control (both `common` and `common-optimized`), animating the widget element.
- **Spacer deco (Clip mode) and the fill layer.** Panel: the Deco Blob section (`framify_deco_section`, condition = shape on) holds the Image widget's deco ids from the same `register_deco_controls()` (variant `'spacer'`): `framify_org_deco` ("Deco blob behind", mode = clip only), deco shape, placement (`deco_*`) and deco motion (`register_deco_motion_controls`, "Same as shape" wording) need mode = clip + deco on. The look controls (`deco_style`, colours, outline width) are shared by both modes because one id can only be registered once: they style the shape in Behind content mode and the extra blob in Clip mode, via `conditions` = `spacer_deco_visible()` (mode deco OR (clip AND deco on)); so in Behind content mode they moved from Organic Shape into this section, same ids and JS path. **Grain:** the container switches stay (saved values carry over): `framify_org_clip_grain` ("Grain on shape fill", default off) and `framify_org_deco_grain` (default on, Solid only, same OR). **Fill layer (why):** clipping the host, as Containers do, clips everything inside it, so a deco could never spill past the shape. `setupFill()` (Clip mode with the deco on ONLY; with it off the host clip is kept, so existing Clip Spacers still cut their Floating Shapes / Text, border and shadow to the shape; toggling the deco rebuilds onto the other path) moves the Spacer's background onto `div.framify-organic__fill` (aria-hidden, pointer-events none, z-index -1, insets = minus the host's border widths, so it covers the border box the old clip used): `takeBackground()` copies the host's computed background-* longhands (color, image, size, position, repeat, origin, clip, attachment, blend-mode) plus the four corner radii, then hides the host's own with inline `background: none !important` (its previous inline background-* declarations are restored exactly on teardown), all with `transition: none` held briefly so a rebuild never reads a mid-fade value or fades the host out. Only the fill gets the clip-path; the clip grain layer is its child, so the fill's clip cuts it. **Fill margin:** a fill exactly the host box had nothing to paint where the shape leaves the box (Liquid's outward ripple, Gentle's swell, Placement > 100% or offsets), so those parts were cut in straight lines at the box edges. The fill therefore reaches `fillMargin()` = round(min(`FILL_MARGIN_MAX` 200, `FILL_MARGIN_RATIO` 0.2 x the host's larger side)) px past the border box on every side (insets = -(border + M)); 20% is over 3x the strongest motion (~5-6% of the box) and leaves room for an overhanging Placement, the cap bounds a wide Spacer. `place()` maps the shape back into the host box with `fillBox()` (x' = (M + x W) / (W + 2M), w' = w W / (W + 2M), same for y / h with H; zoom origin from the same box; Gentle's aspect stays in host pixels). `takeBackground( el, fill, M )` also grows non-zero corner radii to r + M (percentages resolved against the host box; the fill is the rounded box offset outwards) and, when there is a background image, moves each non-fixed layer's background-position-x/y by M(1 - 2p) px (p = its percentage part: +M at 0%, 0 at 50%, -M at 100%), so the image stays anchored to the host box; a percentage / cover background-size resolves against the larger fill, so such an image is scaled and cropped slightly differently. Colours and gradients just cover the larger fill. `refill( M )` re-copies on a device change OR a margin change (host resize). An ancestor with overflow hidden still crops, like the deco. The deco (`ownDeco()`, shared with the Image widget, id `id-deco` so its grain filter id never collides with the clip grain's) is inserted before the fill: same z-index -1, so tree order puts it under the fill; placed with `positionDeco()` in % of the host box; its own channel/rotate as on the Image widget. `spill()` sets inline `overflow: visible` on the host and widget element only where the computed overflow is not visible, and only when a deco is on (restored on teardown); an ancestor Container with overflow hidden can still crop the ring. Hover: the trigger listens on the (now unclipped) host box, like the Image widget's. **Not mirrored:** the Advanced hover background (`_background_hover_*`): the suppression hides it and re-reading on hover would sample mid-transition values; also, with the deco on, a host border / box-shadow and Floating Shapes / Text are no longer cut to the shape. **Breakpoints:** background and border controls are responsive but the fill is an inline snapshot, so `place()` (reached by resize, editor device switch, rotation) calls `refill()`: when `elementorFrontend.getCurrentDeviceMode()` differs from `fx.fillDevice` it restores the host's background and re-runs `takeBackground( el, fx.fill )` into the same fill (insets and radii included). **Editor:** `onElementChange` rebuilds (120 ms + one frame, `scheduleFill`) on `FILL_KEYS` (`_background_`, `_border_` prefixes, `_hover` keys skipped; not the Space height, which the fill follows through its CSS insets) when a fill exists; Spacers also listen on their settings model (`watchSpacerModel`, as `FramifyFx.editorMixin` does) so `$e` commands and undo reach it. Containers and the Image widget keep their paths unchanged.
- **Editor handle** (`keepHandle()`, editor only: `elementorFrontend.isEditMode()`). Elementor's settings handle lives in `.elementor-element-overlay` inside the element (a Container's at the top centre, inside the box with `e-handles-inside` at the top of the page, else just above it; a widget's at the top right), so a clip-path on the element cut it off and clicks there hit the page behind. Wherever the clip lands on the element that owns the overlay (Container Clip mode, a Spacer host clip with Optimized Markup; `el === this.$element[ 0 ]` in `setupContainer`; not the Image widget, whose clip is on the img, nor the Spacer fill path) a `rect.framify-organic__handle` over the handle box (+ `HANDLE_PAD` 2 px, objectBoundingBox units of the element) is added to the clipPath (clipPath children are a union) while the handle shows: on mouseenter, and while the element has `elementor-element-editable` (MutationObserver on its class). It is re-measured every frame for `HANDLE_TRACK` 450 ms after showing, because Elementor slides the handle for 0.3 s. On leave the rect AND the handle (inline `display`, Elementor's hide rule has no !important) stay `HANDLE_GRACE` 800 ms, so the pointer can cross unclipped space to reach it; reaching it re-hovers the element. Teardown removes listeners, observer, timers, inline display and rect. The published front end never runs it.
- **Not bugs (by design):** a Container's deco sits at z-index -1 inside its isolated container, so it is always behind *every* child, including a child container's own deco. To put one blob (e.g. an outline ring child) under its parent's blob, give that child Advanced > Z-index -2 (anything else in that child goes under too). Pattern 0 seeds grain from `data-id`, so repeated items (Loop Grid, global widgets, templates) that share an id share a speckle.

### Floating Shapes

[framify-elementor-shapes.php](framify-elementor-shapes.php) (`Framify_Elementor_Shapes`) + [assets/framify-shapes.js](assets/framify-shapes.js) / [assets/framify-shapes.css](assets/framify-shapes.css): small inline SVG shapes (square, circle, triangle, star, diagonal, plus, x, hexagon) drifting across a Container or legacy Section, as calm confetti.

- **Hooks:** `elementor/element/{container,section}/_section_responsive/after_section_end` at priority 20, so on Containers the section lands after Organic Shape / Grain. **Spacer:** also `elementor/element/spacer/section_spacer/after_section_end` at 20 (same `register_controls`), and `attachHandler( 'spacer', FloatingShapes )` (default skin). The layer's host is `FramifyFx.hostOf( handler )`: the element itself for Containers / Sections, and for a Spacer the element that paints its background (see the Spacer bullet under Elementor module), so the layer fills the Spacer area; with no content, Background and Overlay both simply sit above the Spacer's background. **Image widget:** `elementor/element/image/section_style_caption/after_section_end` at 20 (after Organic Shape / Deco Blob / Grain at 10; Floating Text at 30), `attachHandler( 'image', FloatingShapes )`; the layer goes into a photo frame (see "Image widget photo frame" below), and the Layer control carries the Image-only note `Framify_Elementor::image_layer_note()` ("Behind content is hidden by an opaque photo unless Organic Shape cuts it."). Reuses `Framify_Elementor::TAB`; never registers the tab. Assets are enqueued on `elementor/frontend/after_enqueue_scripts`, filemtime-versioned.
- **Controls:** section `framify_fs_section`, every id prefixed `framify_fs_`, all `live()` (frontend_available + render_type none). `framify_fs_count` is responsive; `readCount()` uses `getCurrentDeviceSetting()` and walks up the breakpoints itself when a device holds an empty slider object (Elementor accepts that as a value). Settings follow the Elementor module rule above (defaults present, empties dropped): `framify_fs_enable` / `framify_fs_spin` are on only when `'yes'`, a missing palette slot is empty (only when all five are empty does the JS fall back to `#F69216`), and selects/sliders keep their harmless default fallbacks. The five colour slots have the Global Colour picker disabled. The CLI test (section 5) checks ids, tab, live flags and defaults.
- **Hexagon** (`framify_fs_shapes` option `hexagon`, included in the default list of eight so sections that never customised the picker gain a hexagon too): a regular pointy-top hexagon (vertices at -90/-30/30/90/150/210 deg, radius 38, same 0-100 box and padding as the circle), corners very slightly rounded by `roundedPolygon()` -- a small helper that cuts each edge back by a fixed amount and bows a quadratic curve through the true vertex, echoing the square's `rx=6` softness. One `path`, built with `createElementNS`/`setAttribute('d', ...)` like every other shape; solid fills it, outline strokes it with the module's usual `vector-effect: non-scaling-stroke` + outline width.
- **Custom speed** (`framify_fs_speed` option `custom`): a responsive slider `framify_fs_duration` ("Seconds per pass", unit `s`, 2-60 step 0.5, default 12, shown only when Speed is Custom) sets the base cycle directly instead of picking a slow/normal/fast constant. `readDuration()` mirrors `readCount()`'s fallback chain (`getCurrentDeviceSetting()`, then walk the breakpoints by hand, then desktop, then 12), clamped 2-60. Every shape still varies about +-40% around that base exactly like the presets (the per-shape jitter in `makeItem()` is unchanged). `watchSize()`'s resize handler rebuilds not only when `readCount()` changes but also when `readDuration()` changes for a custom speed, so switching device in the editor picks up the new duration without waiting on a Count-driven rebuild.
- **JS model:** the script only builds, measures and re-rolls; CSS animates. Per shape three nested layers: `.framify-fs__shape` drifts + fades (`framify-fs-drift`), `.framify-fs__sway` wobbles across the drift, the `svg` spins. Per-shape numbers are custom properties; travel distance is `calc()` over the wrapper's `--fs-w` / `--fs-h`, so a resize (ResizeObserver, one rAF) only rewrites two numbers; crossing a breakpoint whose Count differs rebuilds. One depth value per shape sets size, opacity and speed together. Negative delays start the field full; each `animationiteration` of the drift (shape invisible) re-rolls lane, direction (Random), type, style and colour.
- **Layer stacking (decision):** the background layer is **z-index 0 inserted after Elementor's own background children** (`BACKGROUND_CHILD`: legacy `.elementor-background-overlay`, video, slideshow, motion-effects, the editor's element overlay), not z-index -1. At -1 it painted under a container's `::before` background overlay; at 0 it paints in tree order among positioned boxes: after the overlay, before widgets/child containers (Elementor makes those `position: relative`). Verified in the browser on a Container and on a Section with a 30% overlay. The overlay layer is appended last at z-index 5 with `pointer-events: none`. The host gets `.framify-fs-host` (`isolation: isolate`, so z-index 5 cannot rise above a sticky header elsewhere) and inline `position: relative` only when it was static; both are restored on teardown.
- **Editor:** `onElementChange` (panel controls) and a listener on the element's settings model (undo/redo and `$e` commands, which fire no control view) both debounce a rebuild at 120 ms.
- **Reduced motion:** a still scatter with random opacity (`.framify-fs--still`), plus a CSS media-query fallback; a `matchMedia` change listener rebuilds. **Off-screen:** an IntersectionObserver toggles `.is-paused` (animation-play-state).
- **Performance / security:** count capped at 60; only transform and opacity animate, `will-change` on shapes; outlines use `vector-effect: non-scaling-stroke` (Outline width is real px) and `overflow: visible` so thick strokes on small shapes are not cut. Shapes are built with `createElementNS`, colours via `setAttribute`.
- **Shared helpers (`window.FramifyFx`, defined at the top of framify-shapes.js):** `pick` / `size` / `clamp` / `rand` / `any`, `readColors( s, prefix )` + `pickColor()` (palette / random hue), `readResponsive( handler, key, def, lo, hi )` (the Count / Duration fallback chain), `hostOf( handler )` (the layer host: the element, or a Spacer's background-painting child), `claimHost( el )` (reference-counted `position: relative` + `.framify-fs-host`, returns a release fn, so removing one layer never strips what another still needs), `insertLayer( el, layer, overlay, after )`, `photoFrame( handler, over )` (below), `watchVisible()`, `editorMixin( Base, prefix, ignore )` (onElementChange + settings-model listener + debounced rebuild + onDestroy; `ignore` is one key prefix or an array of them, and a change to an ignored key calls the handler's optional `onStyleChange( key )` instead of rebuilding). Floating Text uses them; change them with both modules in mind.
- **Image widget photo frame (`FramifyFx.photoFrame( handler, over )`).** On the Image widget a layer covering the widget would also fill the empty space beside a narrow centred photo, so each layer goes into a frame (`div.framify-fx-frame--behind` / `--over`, aria-hidden, pointer-events none) sized in px to the img's offset box within the widget (`offsetIn()`: offsetParent chain, so the img's zoom transform never moves it). State lives on the widget element (`el.framifyFxPhoto`), reference-counted: at most one Behind and one Over frame, shared by Floating Shapes and Floating Text; the last release removes the frames, the `.framify-fx-photo` class and the `claimHost()` claim. Re-measured (one rAF) on a ResizeObserver of the widget AND the img, the img's `load` (lazy-load / srcset) and window resize (editor device switch); the img is re-queried each measure, so a re-rendered img is picked up. Returns null off the Image widget or without an img (callers keep `hostOf()`). **Stacking** (the widget is isolated): Organic deco blob (z 0, first child) < Behind frame (z 0, `insertLayer( host, frame, false, '.framify-organic__deco' )`, i.e. after the deco and Elementor's overlay) < img (`.framify-fx-photo img`: relative, z 1, also without Organic Shape) < image grain layer (2) < Over frame (z 3, appended). Layers keep their classes inside a frame, so text stays above shapes (tree order behind, 6 vs 5 over). Behind content only shows where Organic Shape cuts the photo away. **Over frame + Organic Shape (coupling decision):** the frame copies the img's inline `clip-path`, `transform` and `transform-origin` (string copies, only when changed) in `sync()`, which framify-elementor.js calls through `syncPhoto( fx.el )` after every Organic `render()` and after `teardown()`. The objectBoundingBox clip resolves against the frame's box = the img's box, so the frame is cut to the same moving, zooming shape (the Part-1 motion inset included, same url) and a rebuild's new clip id or a toggle off (plain rectangle) is picked up at once, with no polling rAF. Chosen over a frame-side rAF because Organic owns those values and already runs once per frame while moving; the hook is a property check on the element, so script load order does not matter. Verified in the editor preview (unsaved): frame box == img box (also 1024 px img in a 1140 px widget), cut-away corners hit the Behind frame, centre hits the img, the Over frame's computed clip-path and transform equal the img's during a hover zoom. Like image grain, it copies only Framify's inline zoom, not a CSS `:hover` transform from Elementor's Hover Animation.

### Floating Text

[framify-elementor-text.php](framify-elementor-text.php) (`Framify_Elementor_Text`) + [assets/framify-text.js](assets/framify-text.js) / [assets/framify-text.css](assets/framify-text.css): words and short phrases from a list appear one at a time in quiet, non-overlapping spots, hold, and leave, behind the content or over it.

- **Hooks / assets:** same container + section hooks as Floating Shapes at priority 30 (lands after it). **Image widget:** the image hook at 30 via `register_spacer_controls()` (descendant selectors `{{WRAPPER}} .framify-ft`, as the layer sits in a photo frame and an Image widget has no child elements), `attachHandler( 'image', FloatingText )`, same Layer note and `Fx.photoFrame()` as Floating Shapes. **Spacer:** `section_spacer` hook at 30 via `register_spacer_controls()`, `attachHandler( 'spacer', FloatingText )`, host `FramifyFx.hostOf()`. Both public methods feed one `register_section( $element, $layer )`: containers / sections pass `{{WRAPPER}} > .framify-ft` (direct child, so a nested container's layer keeps its own styles); the Spacer passes `{{WRAPPER}} .framify-ft`, because its layer sits inside `.elementor-widget-container` (or directly in the widget with Optimized Markup), and a Spacer has no child elements for a descendant selector to leak into. Script handle `framify-text` depends on `framify-shapes` (it reuses `window.FramifyFx`; decision: share rather than copy the genuinely identical settings, colour, responsive, host/stacking, observer and editor-sync code); style depends on `framify-shapes` (`.framify-fs-host` isolation). filemtime versions.
- **Controls:** section `framify_ft_section`, prefix `framify_ft_`, all `live()` except the Typography group (`framify_ft_typography`, selector `{{WRAPPER}} > .framify-ft .framify-ft__word` on Containers / Sections, `{{WRAPPER}} .framify-ft .framify-ft__word` on the Spacer, default 28px / 600, tablet 24, mobile 20) and the CSS-only Word Style controls (below).
- **Word size = MIN/MAX range (decision, supersedes Size variation + Max font size cap).** The Typography font size is the MAXIMUM; `framify_ft_min_size` (responsive px slider 6-200, default empty, `live()`, first control under the Word Style heading) the minimum. Per word, `build()` appends the word unseen, reads `getComputedStyle( word ).fontSize` BEFORE any inline size (= the Typography size of the current breakpoint), and `wordSize( maxPx, fx.minPx )` picks uniformly in [min, max] (empty min = 0.75 x max; min > max is capped to max, never swapped, because tablet / mobile inherit a desktop min through `readResponsive` and a word must never exceed the Typography size; low end >= 4px). The result is written inline as the WORD's (chip's) `font-size`; mask / text / letters / caret inherit it, so default em pill padding + em radius scale with the word (px Padding values stay px, by choice). `--ft-scale`, `--ft-max` and the CSS `min()` cap are gone; `framify_ft_size_var` / `framify_ft_max_size` were removed and saved values are ignored (existing elements get 75-100%, close to the old +-25%). `fx.minPx` = `readMinSize()` (`FramifyFx.readResponsive`, NaN when empty). Min size is JS-read (not in `CSS_KEYS`), so a change rebuilds; a Typography change stays CSS-only (`onStyleChange` refit) and new words pick up the new max, holding words keep theirs until they leave. `watchSize()` rebuilds on any device-mode change (`fx.device`), because the range changes per breakpoint and on-screen words carry a px size.
- **Word Style** (heading `framify_ft_word_style`, directly after Typography; `register_word_style()`): `min_size` (above); `bg_mode` none|fixed|palette (default none, the only live one here); `bg_color` (fixed only, default #FFFFFF, writes `--ft-bg` on the chip; CSS-only, so its Global Colour picker stays ON, unlike the JS-read colours); `bg_opacity` 0-1 step 0.05 (default 1, fixed + palette, writes `--ft-bg-a`); Border group `framify_ft_border` and responsive `radius` DIMENSIONS on the chip; Text Shadow group `framify_ft_text_shadow` on `.framify-ft__text` (letters inherit it); responsive `padding` DIMENSIONS on the chip. CSS-only ones are `render_type ui` with `selectors` (`css()` helper). Every default writes nothing, so existing elements look exactly as before.
- **Chip structure:** `.framify-ft__word` IS the chip: background / border / radius / padding / typography land on it, it is the box `place()` measures (`box-sizing: border-box`, so the fixed px width / height include padding + border) and positions, and Tilt / Drift transform it whole. It carries the word's final font size inline and is `display: flex` so no line-box strut pads it. Inside: the mask (text opacity, Rise clip; inherits the size) and the text (animations, text shadow). The chip never moves on its own; when dressed (a Background mode, or a non-zero border from the CSS) it fades: in over the first half of the entrance (<= 450 ms), out over the last 60% of the exit (typewriter: a 250 ms fade after the erase). Rise clips the text inside the still chip (decision: a label whose text rolls in reads better than a sliding pill). Undressed words never animate the word's opacity.
- **Chip background:** layer class `framify-ft--chip` (bg_mode not none) gives a crafted default pill (`padding: 0.3em 0.8em`, `border-radius: 999px`, em of the word's final size, overridden by the controls) and `background-color: color-mix( in srgb, var(--ft-bg) calc( var(--ft-bg-a) * 100% ), transparent )` (inside `@supports`, with plain `var(--ft-bg)` as the base rule; a var() declaration always parses, so an unguarded second line would never fall back). **Opacity (decision):** Max opacity (x0.75-1 jitter, `w.alpha`) sits on the mask for an undressed word (text only, as before). A dressed word (`w.chip`, decided once when it enters: a Background mode or a non-zero border) moves it to the whole chip (`word.style.opacity`, and `chipFade` runs 0 <-> `w.alpha`), with the mask back at 1, so the text is full strength inside a chip that fades as one; Background opacity stays relative to the chip background only.
- **From palette:** `chipColors( pickColor() )`: `parseColor()` (#rgb/#rgba/#rrggbb/#rrggbbaa, rgb()/rgba(), hsl()/hsla(), comma or space syntax; else null) -> the chip gets `--ft-bg` as a rebuilt `rgba()` (never the raw setting) and the text colour is `contrastText()`: whichever of `#1E1E1E` / `#FFFFFF` has the higher WCAG contrast ratio ((L1 + 0.05) / (L2 + 0.05)) against the chip, ties dark (e.g. #F69216: dark 7.18:1 vs white 2.32:1). An outline word's stroke is currentColor, so it takes the contrast colour too. Unparseable colour = `#F69216` chip (dark text).
- **Editor sync of CSS-only keys:** `CSS_KEYS` (typography, bg_color, bg_opacity, border, radius, text_shadow, padding prefixes; the CLI test checks it against the PHP) are ignored by the mixin; `onStyleChange` waits 120 ms + one frame for Elementor's CSS, then `fontReady()` + `refitHolding()`. Refit re-measures and re-centres HOLD words; one whose box grew into an older visible word or out of the band leaves early (`leaveEarly()` runs its hold timer now), so the no-overlap rule keeps holding. Count responsive 1-20 (5); Duration responsive (Custom speed). Settings rule as above: switches `'yes' === v`, missing colour = cleared, select/slider fallbacks equal the PHP defaults. Empty words = no layer (the editor warns once: "Framify: Floating Text has no words.").
- **Words:** one per line, whitespace collapsed, duplicates dropped, max 200 lines x 120 chars; written only with `textContent` (letters as `span`s via `createElement`). A line is never on screen twice at once: with fewer free lines than slots a slot waits instead of repeating; recently shown lines are avoided when possible.
- **Slots:** N loops, first entrances staggered over one cycle. Each: pick line -> build unseen (`.is-measuring`) -> measure -> fix the word box (width/height px, so typewriter/scramble/tilt never shift it) -> rejection-sample up to 12 spots inside the band (padding max(8px, 4%)), clear of every visible word's rotated bounding box plus a margin, stretched along the drift path for Drift -> IN -> HOLD -> OUT -> gap (+0-300 ms jitter). No spot = retry later, never overlap.
- **Animations** (`ANIMATIONS` in JS must match `animation_options()` minus `random`; the CLI test checks): fade, drift (40-80 px over in+hold+out, tilt kept in the same transform), typewriter (letters shown one by one behind `.framify-ft__caret`, erased in reverse), blur, pop (overshoot 1.06), rise (clip box `.framify-ft__mask`), cascade (letters staggered <= 40 ms), flip (rotateX with perspective), wave (letters bob, endless animations cancelled with the word), scramble (A-Z0-9 resolving left to right). Random = one per word. Web Animations API everywhere plus a pausable timer list (`later()`), so `setPaused()` freezes timers and animations off-screen and resumes exactly.
- **Stacking with Floating Shapes:** background text layer is z-index 0 too, inserted after Elementor's background children AND after a `.framify-fs` layer, so text paints above shapes by tree order while staying under the content (a higher z-index there would lift it over widgets). Overlay text is z-index 6 vs shapes 5. Verified: shapes rebuilt later still insert before the text layer.
- **Web fonts:** `document.fonts.ready` resolves at once for a Typography font nothing has requested yet, so `fontReady()` reads the computed `font` of a hidden probe word and calls `document.fonts.load( font, sample )` (rejections swallowed, wait capped at `FONT_WAIT` = 1500 ms) before the first stagger; a typography change in the editor calls it too. While the layer lives, a `document.fonts` `loadingdone` listener runs `refitHolding()`: only words in HOLD are re-measured and re-centred (removed on teardown).
- **Letters are graphemes:** `graphemes()` splits with `Intl.Segmenter` (grapheme) when present, else `Array.from`, so a combining accent stays with its letter and a ZWJ emoji stays one span; the 120-char cap is grapheme-safe too. Words containing a joining script (`JOINING`: Arabic blocks, Devanagari and the Indic blocks U+0900-0DFF) never get a letter animation: typewriter / cascade / wave / scramble become fade for that word (also inside Random mix); whole-word animations still apply.
- **WordPress emoji script:** its body MutationObserver would swap emoji for `<img>` after measuring. The mask span carries `wp-exclude-emoji` (it skips children with that class) and scramble writes `nodeValue`, which is no childList mutation.
- **Reduced motion:** fade only, no letters, hold x1.6; a `matchMedia` change rebuilds. Style Outline uses `-webkit-text-stroke` only when `CSS.supports` says so, else solid.

### Shape Divider

[framify-elementor-divider.php](framify-elementor-divider.php) (`Framify_Elementor_Divider`) + [assets/framify-divider.js](assets/framify-divider.js) / [assets/framify-divider.css](assets/framify-divider.css): a Top and / or Bottom divider on a top-level Container, drawn from pasted SVG code / path data or a Media Library SVG, one colour, static or Liquid.

- **Hook / panel:** container `_section_responsive/after_section_end` at 50 (after Float at 40), section `framify_org_dv_section`, controls tabs `framify_org_dv_tabs` (Top / Bottom); per side `framify_org_dv_{top|bottom}_`: `source` ('' None | code | media, default None), `svg` (TEXTAREA), `media` (MEDIA, `media_types` svg, note about Elementor's "Enable Unfiltered File Uploads"), `color` (#FFFFFF, Global Colour off), `width` / `height` (responsive, CSS only: selectors on `{{WRAPPER}} > .framify-dv--side > svg`, render_type ui, in the JS `CSS_KEYS` ignore list), `flip`, `upside`, `front`, `motion` (static | liquid), `trigger` (loop | inview | hover), `amount`. Everything else is `live()`. Ids share the `framify_org_` prefix, so the Organic handler's `onElementChange` skips `DIVIDER_PREFIX` (`framify_org_dv_`) instead of rebuilding.
- **Top-level only:** the JS returns on `.e-child`; the editor script puts `.framify-divider-off` on the panel for a NESTED container (the inverse of Float, same `panel/open_editor/*` hooks) and framify-elementor-editor.css hides `[class*="elementor-control-framify_org_dv_"]`.
- **Sanitiser (shared, framify-elementor.js):** `window.FramifyOrganicShape` exposes `parseCustom`, `parseSvgShape`, `svgGeometry`, `traceCustom`, `customTransform`, `parsePath` / `blendPath`, `elastic` / `easeInOutSine`, `CUSTOM_AMOUNT`. `parseSvgShape( text )`: bare path data, or markup that is not well-formed XML, goes through `parseCustom` (the Custom shape rule). Otherwise `DOMParser` (image/svg+xml) builds a detached document that is never inserted; `walkSvg` reads only `SVG_GEOMETRY` (path, rect, circle, ellipse, line, polyline, polygon), walks only `SVG_GROUPS` (g, a, nested svg as a group), skips `display="none"`; every other element (script, style, image, use, foreignObject, text, defs, clipPath, mask...) and attribute is ignored. Each shape becomes absolute M / L / C / Z built from numbers (`pathCommands` handles packed arc flags; arcs via `arcToCubics`, Q / T / S to cubics), with its own and its ancestors' `transform` attributes (`parseTransform`: matrix / translate / scale / rotate / skewX / skewY; an unreadable transform drops the element) applied; the output is re-checked against `PATH_CHARS`. Box = root viewBox, else numeric width / height, else the measured bbox. Result = parseCustom's shape plus `parts` (one d per source shape). Limits: 200000 chars, depth 32, 2000 shapes. Not supported: CSS transforms, `use`, per-shape fill-rule / opacity, % / em lengths (shape dropped). Node unit test: `node dev/tests/divider-sanitiser-test.js` (DOMParser stand-in; the PHP CLI test runs it too).
- **Media:** the control's `url` (on the live page the MEDIA value reaches data-settings as an object) is fetched only when `new URL( url, location.href ).origin === location.origin` (and again on the response URL), `credentials: same-origin`, max 200000 chars, one request per URL per page; the text then goes through `parseSvgShape`.
- **Rendering:** `div.framify-dv.framify-dv--top|bottom` (aria-hidden, absolute, `top` / `bottom: -1px` like Elementor, overflow clipped sideways only) holding an svg (viewBox 0 0 100 100, preserveAspectRatio none, width % centred, height px). One `path` per source shape (static, with `customTransform( box )`) or per traced part (Liquid): overlapping shapes merged into one path cancelled by winding. Fill = `style.fill`. **Orientation (Elementor's convention):** art is drawn for the top edge; Bottom = `rotate(180deg)` on the strip (mirrors, like Elementor); Flip = scaleX(-1), Upside down = scaleY(-1) on the svg, so the art's bottom then touches the container edge. **Stacking:** host claimed with `FramifyFx.claimHost` (relative + isolation), layer z-index 0 inserted after Elementor's background children and any Framify fs / ft / organic deco / fill layers, so it paints above the background, a fill / deco (-1) and background Floating layers, below content; Bring to front = z-index 2 (as Elementor). Organic Clip mode on the same container clips the divider too.
- **Liquid:** `traceCustom( shape, box, amount, [ upside ? 'bottom' : 'top', 'left', 'right' ] )` (`pinDistance` accepts a list of sides; Organic still passes one). The traced Catmull-Rom curve overshoots the pinned lines at corners, so `clampTraced()` clamps x to 0-100 and y to the pinned side (M / C only, numbers alternate x, y; structure unchanged). The Liquid svg uses viewBox `4 0 92 100` (`LIQUID_VIEWBOX`): the trace rounds the band's ends over about one point spacing, a visible curl on a wide container; the ends are pinned, so the cropped part is still. Motion: Loop = cosine swing (`LOOP_MS` 5000) while visible (`FramifyFx.watchVisible`), In view = once (threshold 0.35), Hover = on the container; spring 1500 ms `elastic( 0.45 )`. Reduced motion = static (a `matchMedia` change rebuilds). Liquid rest is the smoothed trace, not the exact shape; holes inside one shape are filled in Liquid.
- **Editor:** `FramifyFx.editorMixin( Base, PREFIX, CSS_KEYS )` (panel + settings model, 120 ms debounce). Teardown removes layers, listeners, observers, rAF and releases the host.
- **Verified (editor, unsaved; front end):** hostile pasted document (script, onload, image onerror, foreignObject) -> only 3 paths with `d, transform, style`, no flag set, bbox 0-1000 x 0-70 (transform applied); flip / upside classes and matrices; Bring to front hit tests 0 -> 5792 of 5795 on the divider; Liquid Loop Strong: pinned edge constant (-1 / +1 px) while the free edge moves; nested container ignores forced settings and hides the section; media via an SVG shipped in Elementor (no library SVG on the test site); cross-origin URL refused. Front end with nothing saved identical to the page with the divider files blocked (213 elements, 0 diffs, 0 errors, scrollWidth 1366).

## Conventions

- **AJAX**: `wp_ajax_framify_*` → `check_ajax_referer('framify_nonce', 'nonce')` → `current_user_can('manage_options')` → `wp_send_json_success/error`. Every handler, including read-only ones.
- **JS**: jQuery IIFE, `var`, no modules, no transpilation. CodeMirror 5.65.16 comes from cdnjs (both apps hardcode the URLs; keep versions in sync).
- **Comments** explain *why*, not what. Several load-bearing decisions in this codebase only exist as a docblock — read them before "simplifying".

## Traps

- **Never round-trip these files through PowerShell `Get-Content`/`Set-Content`.** It mangles UTF-8 and adds a BOM, which is fatal in a PHP template. The editor template and script are deliberately pure ASCII — keep them that way (SVG icons and HTML entities, not glyph characters).
- The SEO analyser's entire UI JavaScript is **inline** in [framify-seo.php](framify-seo.php) (roughly lines 497–1013). `assets/framify-seo.js` is a 0-byte placeholder — editing it does nothing.
- `assets/admin-style.css` is also 0 bytes but is enqueued, and `assets/admin/`, `assets/gutenberg/`, `assets/preview/` are empty directories.
- `templates/all-codes.php` and `templates/add-code.php` **do not exist**. The hidden `framify-all` / `framify-add` admin pages render a "Template not found" placeholder, and roughly half of [assets/admin-script.js](assets/admin-script.js) targets markup that is never printed.
- The `framify` top-level admin menu item does not render a page — it redirects to the live-preview URL.
